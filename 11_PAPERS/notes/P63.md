## Problem
Educational LLM tutors must follow student intent while enforcing pedagogical constraints; here the "attacker" is the student trying to extract full solutions, so false positives (blocking legitimate help requests) carry direct pedagogical cost (Sec 1, p.1; Sec 3.4, p.3). Security evaluation for educational AI is "largely unaddressed" and no controlled, reproducible benchmark compares guardrail strategies for this answer-extraction threat model (Sec 2.3, p.2). Guardrail choice must be treated as an explicit trade-off among bypass resistance, false-positive rate, and latency rather than an isolated metric (Sec 1, p.2).

## Research question(s)
No numbered RQs. Stated contributions (Sec 1, p.1–2): educational-specific detection patterns; a four-layer defence-in-depth pipeline with 46.34% bypass and 0.00% FPR on the holdout; low-latency execution (2.50 ms); statistical robustness checks; head-to-head benchmarking of Prompt Guard 2 and NeMo Guardrails under one protocol.

## Method / architecture / algorithm
Four sequential layers (Sec 4, p.4–5; Algorithm 1, p.19). Execution order: Layer 1 (input lexical) → Layer 3 (input sandboxing) → LLM inference → Layer 2 (output structural validation); Layer 4 runs asynchronously on the session trace (Sec 4.5, p.5).
- **Layer 1 – Deterministic filtering** (Sec 4.1, p.4): 30 curated regular expressions grouped as English jailbreak patterns (e.g., `ignore.*previous.*instructions`, `you are now .*`), Portuguese patterns (`ignorar.*(tudo|todas)`, `modo.*(desenvolvedor|admin)`), and educational extraction patterns (`give.*full.*solution`, `code.*to.*paste`).
- **Layer 2 – Structural integrity** (Sec 4.2, p.4): JSON-structure constraints on *model outputs* — expected shape `{title, description, buggedCode, correctCode}` (all strings); length and required-field constraints validated after parsing; any extra field, missing key or type mismatch is rejected before delivery. Also scans for HTML/XSS-like patterns (`<script>`, `<iframe>`, `javascript:`, `on\w+\s*=`, `data:.*base64`).
- **Layer 3 – Contextual sandboxing** (Sec 4.3, p.4–5): user input wrapped in explicit `<USER_CODE>` delimiters in the system prompt; enforces boundary integrity (delimiter-escape detection), control-character removal, length caps on code/OCR payloads.
- **Layer 4 – Behavioral heuristics** (Sec 4.4, p.5): consecutive-block count ≥ T triggers session-level intervention (rate limiting/cooldown); inter-arrival time below a threshold flags the session. Blocks zero attacks in the offline single-turn benchmark by design (Sec 4.5, p.5; Appendix A.3, p.19).
- **Threat model** (Sec 3.1, p.2–3): black-box student-level adversary via normal input channels; excludes network attacks, model access, data poisoning and indirect injection via retrieved documents (Sec 3.5, p.3–4). Six attack families (Table 1, p.3): Instruction Override, Role Hijacking, Format Bypass, Multi-turn Escalation, Prompt Exfiltration, Obfuscated/Encoded.

## Dataset(s) (+ size, licence) / benchmark
Synthetic benchmark of 480 queries (369 injection / 111 benign; 77% injection "worst-case" skew) generated by an LLM-assisted pipeline with human-in-the-loop review, from a deterministic persona×scenario question bank; languages EN and PT-BR; metadata: persona (red team tester, deadline student, teaching assistant, curious beginner, career switcher), scenario, language, turn index (Sec 5.1, p.5). A stratified 20% calibration split is used only for external-classifier threshold selection; metrics are reported on the disjoint 80% holdout (Sec 5.1, p.5; Sec 5.4, p.7). Multi-seed regeneration with 10 seeds (42, 1337, 2024, 101, 202, 303, 404, 505, 606, 707) (Sec 5.4, p.7). Data released in the reproducibility package (Data availability, p.16). Licence: Not reported. Illustrative (non-verbatim) samples in Appendix A (p.18–19).

## Baselines
No Defense; Layer 1 Only (regex); Prompt Guard = Hugging Face `meta-llama/Llama-Prompt-Guard-2-86M` with threshold calibrated on the 20% split to target FPR ≤ 1% (calibrated default ≈0.031) plus an 11-point threshold sweep; NeMo Guardrails in local config mode via an Azure OpenAI endpoint (model gpt-4.1) with strict / balanced / permissive rails (Sec 5.6, p.8; Sec 5.11, p.12; Table 9, p.13).

## Metrics
Bypass rate (injections passed), FPR (benign blocked), average and p95 latency in ms; stratified bootstrap 95% CIs (3,000 replicates); exact McNemar paired tests; Clopper-Pearson one-sided 95% upper bound for zero-FPR; per-persona and per-language stratification; severity S0–S3 of bypass events judged on the downstream tutor's actual response; direct per-query API cost per 1K queries; throughput (queries/s) (Sec 5.2–5.10, p.5–11).

## Key results (each with table/figure/page reference)
**Hardware: Not reported.** Latencies were captured "with a monotonic high-resolution timer on the same hardware infrastructure used for our multi-layer pipeline" (Sec 5.6, p.8); the author warns that "absolute latency metrics are heavily dependent on the underlying hardware infrastructure (e.g., CPU vs. GPU architecture, RAM, and network conditions for external API calls)" and that 2.50 ms "should be interpreted as the local overhead added by our framework relative to a no-defense baseline on our evaluation hardware" (Sec 5.7, p.9). A Docker reproducibility package is referenced (Sec 7, p.15) but no CPU/GPU model is named.

- Layer 1 Only 69.65% / 0.00% / 0.03 / 0.04
- Multi-Layer (ours) 46.34% / 0.00% / 2.50 / 4.10
- Prompt Guard (86M, local) 38.48% / 3.60% / 74.41 / 86.10

Confusion matrix (Table 2, p.6): benign 111 passed / 0 blocked; injection 171 passed / 198 blocked.

Persona stratification (Table 5, p.10): Multi-Layer bypass 32.76% (career switcher) to 52.05% (teaching assistant), FPR 0.00% for all, latency 2.03–2.77 ms; Prompt Guard FPR 0.00–9.52% (curious beginner 9.52%, deadline student 4.55%, teaching assistant 3.85%), latency 74.20–74.61 ms; NeMo FPR 4.55–28.57%, latency 1305.65–1701.52 ms.

Language stratification (Table 7, p.13): Multi-Layer bypass EN 25.1% vs PT-BR 73.5% (gap +48.3 pp); Role Hijacking PT-BR 100%; 34% of PT-BR injection patterns lack regex rules; 12% of PT-BR bypasses use accented characters; 22% are literal translations (Sec 5.9, p.10–11).

Severity (Table 6, p.13; Sec 5.8, p.10): of 171 input-gate bypasses, 71 were rejected by the provider's responsible-AI layer and 100 reached the gpt-4.1 tutor, which refused/redirected all 100 → 171/171 S0, critical bypass (S2+S3) 0%; author notes this is conditional on the system prompt and provider filter and that the regex-based severity classifier may under-count leakage.

Cost / throughput (Table 8, p.13; Sec 5.10, p.11): direct API cost $0.00/1K for No Defense, Layer 1, Multi-Layer, Prompt Guard (local compute not monetised); NeMo $12.50/1K. Throughput ≈400 queries/s Multi-Layer, ≈13 queries/s Prompt Guard, <1 query/s NeMo.

Sensitivity sweep (Table 9, p.13; Sec 5.11, p.12): Prompt Guard threshold 0.010 → 36.0% bypass / 3.60% FPR; 0.031 (default) 38.5% / 3.60%; 0.050 40.7% / 0.00%; 0.10 48.0% / 0%; 0.30 53.9%; 0.50 56.1%; 0.70 58.8%; 0.85 58.8%; 0.90 60.7%; 0.95 62.3%; 0.99 65.3% / 0%. Per-layer latency (Fig. 4, p.12, caption): Layer 1 sub-millisecond; residual from Layer 2 (structural validation) and Layer 3 (sandboxing) when execution falls through; Layer 4 = 0 ms offline. ## Stated limitations (with location)
- Entirely synthetic dataset; real student traffic may differ; seed sweep limited to 10 seeds (Sec 5.4 "Limitations of Statistical Approach", p.7).
- External validity: (i) offline single-turn protocol, Layer 4 unmeasurable; (ii) single deployment context (programming tutor, EN/PT-BR); (iii) no user-centric outcomes (Sec 5.4, p.7; Sec 6.4, p.14–15).
- Indirect injection (RAG/LMS/file-mediated) excluded (Sec 3.5, p.3–4).
- Absolute latency hardware-dependent; 2.50 ms is local overhead on the author's hardware (Sec 5.7, p.9).
- Severity result conditional on system prompt + provider filter; regex severity classifier may under-count leakage (Sec 5.8, p.10).
- 46.34% bypass at the input gate "indicates significant residual risk on that layer alone" (Sec 7, p.15).
- Local compute for Prompt Guard not monetised (Sec 5.10, p.11).
- PT-BR pattern coverage gap (Sec 5.9, p.10–11).

## Limitations we observe (labelled OURS)
- OURS: Hardware is never specified (no CPU/GPU model, core count or RAM), so the 2.50 ms / 74.41 ms / 1470 ms figures cannot be normalised or reproduced precisely; the Prompt Guard number in particular is unclear as to CPU vs GPU inference.
- OURS: NeMo's latency and cost are dominated by remote Azure OpenAI gpt-4.1 calls, so the comparison mixes local classifiers with a network round-trip; the paper acknowledges network conditions but still ranks them on one axis.
- OURS: Benign set is only 111 queries, so the 0.00% FPR has an upper CI of 2.67–2.70% — weak evidence for "zero FPR" at scale; the multi-layer pipeline's zero FPR is partly by construction, since Layers 1–3 are hand-tuned regex/delimiter checks calibrated against the same benign phrase types (Sec 6.2, p.14).
- OURS: The paper's own pipeline contains no learned/semantic classifier; the only ML component evaluated is the external Prompt Guard. Layer 2 is JSON-schema validation of LLM *output*, which is structural (keys, types, lengths), not semantic validation of input values.
- OURS: The text calls the 480-query set both "the evaluation benchmark" and "the holdout" while also describing a 20%/80% split; whether 480 is pre- or post-split is ambiguous (Sec 5.1–5.2, p.5).
- OURS: Single author, preprint, synthetic data, one domain; the bypass rate is measured against regex-detectable attack phrasing generated by LLMs, which may favour regex defences.
- OURS: The 400 QPS throughput figure has no stated measurement method (Sec 5.10, p.11).

## Relevance to our RQs
- **RQ5 (semantic-layer detection):** PARTIAL. Demonstrates a layered input/output validation pipeline in an LLM-backed web application and includes a JSON-schema output validator (Layer 2) plus XSS pattern checks, i.e., structural validation adjacent to our semantic layer; but no semantic classifier of its own, and the target property is answer extraction, not semantic validity of request fields. The Prompt Guard adapter results (38.48% bypass, 3.60% FPR, 74 ms) are the closest to a "semantic detector in the request path".
- **RQ6 (latency/overhead):** DIRECT numbers for three tiers: regex 0.03 ms, multi-layer 2.50 ms (p95 4.10), 86M-parameter transformer classifier 74.41 ms (p95 86.10), LLM-rail 1470.61 ms (p95 4748.63) (Table 3, p.8) — but with unspecified hardware.
- **RQ7 (trade-off):** DIRECT. The paper's central thesis is that guardrail selection is a security–usability–latency operating-point decision; Table 9 gives a full bypass-vs-FPR curve for Prompt Guard and Fig. 3 (p.11) plots the FPR-vs-bypass frontier; Table 8 adds cost and throughput.
- **FPR on benign inputs:** Explicitly measured and central: 0.00% (n=111, CI upper ~2.7%) for the regex pipeline; 3.60% for Prompt Guard at the FPR-≤1%-calibrated threshold (calibration did not transfer: target ≤1%, achieved 3.60%); 16.22% for NeMo balanced/strict; persona-dependent FPR up to 9.52% (Prompt Guard) and 28.57% (NeMo) (Table 5, p.10).

## Potential gap / novelty evidence (quote LOCATION; short quotes only)
- Sec 2.3, p.2: "security evaluation for educational AI remains largely unaddressed" and "no prior study has provided a controlled, reproducible benchmark comparing guardrail strategies" for this threat model (domain-scoped claim).
- Sec 1, p.2: guardrail choices "should be made as explicit trade-offs among bypass resistance, false-positive behavior, and latency, rather than from isolated metrics" — supports RQ7 framing.
- Sec 5.7, p.9: absolute latency "heavily dependent on the underlying hardware infrastructure" — supports our need for hardware-controlled measurement.
- Sec 5.6, p.8: Prompt Guard calibrated to "target FPR ≤ 1%" on the calibration split but yields 3.60% on holdout — evidence that low-FPR calibration of ML detectors is fragile on domain data.
- Sec 5.9, p.10: 48.3 pp EN/PT-BR bypass gap — regex layers do not generalise across languages, an argument for semantic (embedding-based) layers.
- Absence evidence: no semantic/embedding classifier in the pipeline; hardware unspecified; no test of validity of ordinary (non-adversarial) structured inputs.

## Detector design details useful for our semantic-layer candidates
- Own pipeline: no embedding model; 30 regex patterns + JSON schema validation + delimiter/control-char checks + session heuristics (Sec 4, p.4–5). Regex layer 0.03 ms avg; full pipeline 2.50 ms avg / 4.10 ms p95 (Table 3, p.8).
- External ML detector: meta-llama/Llama-Prompt-Guard-2-86M (≈86M params), threshold selected on a 20% stratified calibration split to target FPR ≤ 1% (chosen ≈0.031), scores cached for the 11-threshold sweep; 74.41 ms avg / 86.10 ms p95; ≈13 QPS (Sec 5.6 p.8; Sec 5.10 p.11; Table 9 p.13). Hardware Not reported.
- LLM-rail detector: NeMo Guardrails + Azure OpenAI gpt-4.1; 1470.61 ms avg / 4748.63 ms p95; <1 QPS; $12.50/1K queries (Table 3 p.8; Table 8 p.13).
- Latency measurement: monotonic high-resolution wall-clock timer, same host for all adapters, bootstrap CIs over per-query latencies, p95 reported (Sec 5.4 p.7; Sec 5.6 p.8).
- Reusable protocol elements: calibration/holdout split for thresholds; Clopper-Pearson bound for zero-FPR claims; McNemar paired tests between defences; persona- and language-stratified FPR; cost-per-1K and QPS alongside latency.
