## Problem
LLMs are deployed to extract structured records (invoices, medical records, PDF→database), but "existing benchmarks for structured output generation either focus on schema compliance alone, or evaluate value correctness within a single source domain" (Abstract, p.1). A JSON output can pass every schema validator while carrying wrong values: "The JSON is valid. The type is correct, but the data is wrong." (Sec. 1, p.2).

## Research question(s)
No numbered RQs. Implicit question (Sec. 1, p.2): how large is the gap between "produces valid JSON" and "produces correct JSON" across models and source modalities, and does model size or modality predict it?

## Method / architecture / algorithm
- Benchmark SOB: each record = (context c, question q, JSON schema s) → (ground truth g, validated output v) (Sec. 3, p.4).
- All models receive text-normalised context (OCR markdown for images, timestamped speaker-labelled transcripts for audio) to isolate structured-output capability from vision/ASR quality (Sec. 3, p.4).
- Evaluation pipeline (Fig. 1, p.2; Sec. 4.1, p.5): parse check → jsonschema.validate → path-flatten to leaf nodes with concrete array indices → field-by-field comparison with ground truth.
- Hardening rule: if a response fails parse/root/schema checks, all semantic scores are zeroed; plus coverage gates (0.95 text, 0.90 image/audio) (Sec. 4.2, p.5).
- Aggregation: schema-complexity-weighted means (easy 1.0, medium 2.0, hard 3.0) (Sec. 4.4, p.6); unified leaderboard with coverage adjustment (Eqs. 4–7, p.6–7).
- Ground truth: human-authored schemas and answers cross-checked by Gemini 2.5 Flash; LLM-as-judge (threshold 60/100) for quality filtering; ~3% residual error on text estimated from five 100-record samples (Sec. 3, p.4; Sec. 7, p.11).

## Dataset(s) (+ size, licence) / benchmark
- Text: 5,000 evaluation records (from a 25,091-record full corpus) derived from HotpotQA (Sec. 3, p.4; Abstract).
- Image: 209 records from OCR-processed PDFs (olmOCR-bench) across seven document types (Abstract; Table 7, p.14).
- Audio: 115 records from the AMI Meeting Corpus via edinburghcstr/ami on HuggingFace (Appendix, p.19).
- Schema complexity: majority "hard" (61% text, 88% image, 98% audio) (Sec. 3, p.4).
- Licences: Not reported in the sections read.

## Baselines
No defence/method baseline; 21 models compared against each other (8B–358B; frontier APIs and open-weight via vLLM) (Sec. 5.1, p.6). Ablation: schema-constrained decoding vs schema-in-prompt for 3 models on audio (Table 3, p.9).

## Metrics
Seven per-record metrics (Table 1, p.5): JSON Pass Rate {0,1} (parse + structured root + jsonschema.validate); Faithfulness [0,1] (token F1); Path Recall; Structure Coverage (path-set F1); Type Safety; Perfect Response {0,1} (exact canonicalised object match); Value Accuracy [0,1] (exact leaf-value match; PRIMARY, Eq. 1, p.5). Inference: temperature 0.0, max 2,048 output tokens, reasoning disabled where possible (Sec. 5.2, p.6).

## Key results (each with table/figure/page reference)
- Best Value Accuracy: 83.0% text, 67.2% image, 23.7% audio, while "models achieve near-perfect schema compliance" (Abstract, p.1; Sec. 6.6 item 6, p.11).
- JSON Pass vs Value Accuracy gap "consistently 15–25 percentage points" across the leaderboard (Sec. 6.2, p.7); Fig. 2 caption (p.8): every model exceeds 84% JSON Pass, no model surpasses 80.4% Value Accuracy (overall aggregation).
- GPT-5.4: 99.97% JSON Pass Rate but Perfect Response 0.486 (~51-point gap); GLM-4.7: 0.972 JSON Pass, 0.526 Perfect Response (Sec. 6.6 item 1, p.9).
- "Structural metrics mask value errors": 16 of 21 text models ≥96% on Path Recall, Structure Coverage and Type Safety, yet Value Accuracy 0.693–0.830 and Perfect Response 0.376–0.526 (Sec. 6.6 item 3, p.10).
- Error taxonomy (Sec. 6.7, p.11): parse failures (19/21 models <2%); schema violations (median compliance 97.5%); value errors — "the dominant gap": 17–31% of leaf values incorrect despite valid structure; missing paths (Path Recall 0.853–0.996); type mismatches (Type Safety 0.858–0.9997).
- Model size does not predict quality: Phi-4 (14B) 0.798 VA > GPT-5 (0.795); Schematron-8B 0.754 > GPT-OSS 20B 0.693 (Sec. 6.6 item 4, p.10).
- Schema-constrained decoding ablation (audio, n=115, Table 3, p.9): Value Accuracy changes only −0.007 to +0.033; JSON Pass rises for Gemini models (0.860→0.956; 0.773→0.869) and falls slightly for GPT-5.4 (0.869→0.808).
- Value Accuracy is exact-match and order-sensitive; "United States" vs "American" scores 0 (Sec. 3, p.4; Sec. 7, p.11).
- Table 10 (p.17) separates (a) genuine value errors (e.g., "15 to 35 years" → "25 to 35", numeric hallucination; inserted "American") from (b) format/paraphrase mismatches (e.g., "ISBN: 978-…" → "978-…").

## Stated limitations (with location)
(Sec. 7, p.11) Ground truth human-authored with LLM cross-check; ~3% residual error on text; schemas reflect the authors' conventions (future: FHIR/UBL production schemas). Images evaluated through validated OCR markdown and audio through gold transcripts, so audio is an upper bound (Whisper ~6–10% WER would degrade further). Exact-match scoring over-penalises semantic equivalents ("USA" vs "United States") and treats all arrays as ordered. LLM-judge threshold and coverage gates are fixed, not ablated. No constrained-decoding baselines (Outlines, XGrammar).

## Limitations we observe (labelled OURS)
- OURS: The benchmark measures extraction fidelity against a source context (ground truth exists), not validity of *generated* form/API inputs against business rules; "value error" here means unfaithful to the context, not semantically invalid per se.
- OURS: No latency or cost figures for the evaluation pipeline; no detection mechanism proposed for value errors beyond field-level comparison with a gold answer.
- OURS: Value errors are not broken down by field/data type (date, numeric, enum, identifier, free text); the taxonomy is by failure mechanism only (Sec. 6.7, p.11).
- OURS: No comparison to non-LLM inputs (random, rule-based, human).

## Future work stated
(Sec. 7, p.11; Sec. 3, p.4) Native image/audio input end-to-end evaluation; semantic-aware comparison (STED) and order-insensitive array flags; sensitivity analysis of judge threshold and gates; constrained-decoding baselines; additional modalities (video, code); live leaderboard; production schemas (FHIR, UBL); MuSiQue/2WikiMultihopQA expansion (Sec. 2.4, p.3).

## Relevance to our RQs
- RQ1 (structural-pass-but-semantic-fail): DIRECT at the *output* side. The whole benchmark quantifies structurally valid JSON with wrong values: 15–25 pp gap (Sec. 6.2, p.7); 17–31% of leaf values wrong despite valid structure (Sec. 6.7, p.11). Strongest external evidence yet that the phenomenon is large and systematic across 21 models.
- RQ2 (frequency by field type): PARTIAL. Reports per-modality and per-schema-complexity rates, and examples of numeric/string/identifier errors (Table 10, p.17), but not a per-field-type breakdown.
- RQ3 (LLM vs random/rule/human inputs): NONE. LLM-only.
- RQ4 (violation types): PARTIAL. Five-class error taxonomy (parse, schema violation, value error, missing path, type mismatch) (Sec. 6.7, p.11) plus the genuine-error vs paraphrase split (Table 10).
- RQ5 (semantic layer detection): INDIRECT. Their "field-level verification against the source" (Sec. 6.6 item 5, p.10) is the oracle, not a deployable detector; motivates one.
- RQ6 (latency/overhead): NONE.
- RQ7 (trade-off): INDIRECT. Table 3 (p.9) shows constrained decoding raises schema compliance without materially improving value accuracy — structural enforcement ≠ semantic correctness.

## Terminology the paper uses for structural-vs-semantic validity
- Structural side: "schema compliance", "schema-valid JSON", "JSON Pass Rate", "structural correctness", "structural metrics", "scaffolding", "syntactic validity", "format adherence", "output contract reliability".
- Semantic side: "Value Accuracy", "value correctness", "grounded values", "faithfulness", "value-level hallucinations", "structured hallucinations", "structured-output hallucination", "value errors: correct structure, wrong content".
- Gating language: "semantic scores" (Value Accuracy, Faithfulness, Path Recall, Structure Coverage) are "hardened"/zeroed on structural failure (Sec. 4.2, p.5).
- Key phrase: the gap between "produces valid JSON" and "produces correct JSON" (Sec. 1, p.2).
