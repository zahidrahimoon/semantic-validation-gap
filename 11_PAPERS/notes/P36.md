# P36 — sigdel2026schemafirst
Verification level: V4 · Read depth: full · Read on: 2026-09-20 · PDF: 11_PAPERS/pdfs/2026_Sigdel_SchemaFirst.pdf
Bibliographic: Schema First Tool APIs for LLM Agents: A Controlled Study of Tool Misuse, Recovery, and Budgeted Performance; Akshey Sigdel, Rista Baral (both "Independent Researcher", boisestate.edu emails); 2026; arXiv:2603.13404v1 [cs.SE] 12 Mar 2026; 9 pages. No venue stated.

## Problem
Tool use is central to LLM agents, "yet interface design is rarely isolated as an experimental variable" (Abstract p.1). A recurring failure mode is "tool misuse, malformed calls, missing required fields, invalid enumerations, and constraint violations that consume budget and propagate downstream errors" (§1 p.1). Production deployments impose strict latency and cost limits that translate to hard step limits, where "a single interface error can be decisive" (§1 p.1). The paper distinguishes "interface misuse" (violations of the tool input contract) from "semantic misuse" (calls that are schema valid but unproductive or inappropriate for the task) (§1 p.2).

## Research question(s)
Central question (§1 p.1): "whether tool interface design can serve as a low cost reliability primitive for LLM agents without modifying model weights." Hypotheses (§4 p.4): H1 (Misuse reduction) — schema-first tool specs reduce interface misuse I vs free-form docs; H2 (Recovery) — structured validation diagnostics increase recovery probability R vs schemas alone; H3 (Budget sensitivity) — gains in task success S from structured diagnostics are larger under tighter budgets. Experimental questions (§6 p.6): (i) misuse reduction, (ii) recovery improvements, (iii) budget sensitivity, (iv) semantic spillover, (v) cost trade-offs (token overhead vs benefit).

## Method / architecture / algorithm
- System model (§3 p.3): agent interacts with a deterministic software-engineering sandbox; task = artifacts (logs, metrics, configs, small repo) + hidden ground-truth issue + deterministic checker J_τ. Each tool has a canonical input contract C(u) (fields, types, requiredness, enumerations, constraints), a representation R_κ(u) per condition κ ∈ {A,B,C}, and a deterministic executor.
- Two notions of validity (§3 p.3): **Interface validity** (schema/well-formedness: JSON validity, required fields, types, enums, numeric bounds) vs **Execution validity** (runtime preconditions: file path exists, metric key available, patch applies). Execution validity held constant across conditions.
- Conditions (§4 p.3): (A) free-form prose documentation; (B) schema-first strict JSON Schema; (C) schema + structured field-level diagnostics (JSONPath, expected type/constraint, allowed values; example on p.5). **Information equivalence** enforced by generating both prose and schema from the same canonical contract (§4 pp.3–4).
- Failure taxonomy (§4 p.4): interface misuse; execution failures; semantic misuse (schema-valid but unproductive/misaligned: wrong tool choice, irrelevant query, repeated calls).
- Outcomes (§4 p.4): task success S, interface misuse rate I, execution failure rate E, recovery probability R, steps-to-success T, semantic misuse rate M, overhead O (prompt-token overhead + extra steps). Primary endpoint: S at tight budgets B ∈ {3,5}; secondary: I, R, area under S(B).
- Sandbox (§5 pp.4–5): logs with injected failure signatures and decoys, metric snapshots, YAML/JSON configs with controlled errors, small repo with deterministic unit tests. Tools: search_logs, get_metric, list_dir, read_file, grep_repo, run_tests, apply_patch. Budgets B ∈ {3,5,8,12}.
- Semantic misuse measurement (§5 p.6): per-task trace oracles (acceptable high-level tool-call traces with branching/partial orders); schema-valid calls inconsistent with all acceptable prefixes count as semantic misuse. Oracle governance: fixed rubric, dual annotation on a stratified subset with Cohen's κ, blinded adjudication.
- Statistics (§5 p.6): mean/median with bootstrap CIs over tasks; Wilcoxon signed-rank for paired comparisons; Holm–Bonferroni correction; inference at task level with seed variability summaries.
- Planned analyses (§6 p.7): recovery-conditioned analysis (B vs C after first invalid call); budget curves; ablation on diagnostic quality C1 (generic message) / C2 (path + expected) / C3 (full: allowed enums, bounds, corrective hints); failure-mode taxonomy (wrong tool name, malformed JSON, missing required field, type mismatch, enum violation, constraint violation, runtime precondition failure, semantic misuse); overhead metrics (success per 1K prompt tokens, invalid calls per 1K prompt tokens); robustness checks.

## Dataset(s) (+ size, licence) / benchmark
Own deterministic diagnostic sandbox (§5 pp.4–5). Reported pilot: "8 task reduced pack" (§7 p.8); 276 scored runs, 2208 step records, 12 excluded runs (§7 p.8). Task families: log-centric diagnosis, config-centric correction, repo-centric debugging/patching, mixed (§5 p.5). Licence: Not reported. Artifacts stated as released (§5 p.6 "Reproducibility"; footnote 1 p.7).

## Baselines
Condition (A) free-form documentation is the baseline against (B) and (C) (§4 p.3). Single model: Qwen2.5 0.5B Instruct, GGUF quantized, seeds {0,1,2}, deterministic decoding, per-step generation length cap (§6 p.6). No other models or external methods.

## Metrics
S, I, E, R, T, M, O as defined in §4 p.4. Efficiency metrics defined (§6 p.7): success per 1K prompt tokens, invalid calls per 1K prompt tokens. In the reported pilot (§7 p.8) only S, mean invalid calls, mean semantic misuse, mean execution failures and exclusions are given numerically.

## Key results (each with table/figure/page reference)
The paper contains no result tables or figures; all numbers are in §7 text p.8.
- Primary endpoint (§7 p.8): "Task success was 0.0 across all conditions and all budgets in this pilot" — primary endpoint uninformative; paired tests return null effects.
- Interface misuse (§7 p.8): mean invalid calls over all budgets A = 5.39, B = 3.72, C = 3.72 — "consistent with directional support for H1 at the misuse level."
- Semantic misuse (§7 p.8): higher in schema conditions — A = 0.93, B = 3.03, C = 3.03 — "indicating that remaining errors are dominated by schema valid but unproductive action choices."
- Execution failures (§7 p.8): A = 0.54, B = 0.00, C = 0.00. All 12 exclusions were infrastructure timeouts in one repository-debug task family instance.
- Budget trends (§7 p.8): invalid and semantic misuse counts increase monotonically with budget in all conditions without success gains — "a recovery policy and semantic planning limitation … rather than a pure schema compliance limitation."
- Interpretation (§7 p.8): "schema first interfaces reduce interface format errors, but under constrained local inference, semantic action quality and timeout sensitive tasks dominate end to end outcomes." Claims scoped to "a one model, three seed pilot."
- B and C produce identical numbers for I and M (§7 p.8); no recovery-conditioned, ablation (C1–C3), or overhead results are reported.

## Stated limitations (with location)
§5 p.6 / §6 p.6: one-model pilot, "compute constrained and is interpreted as a focused pilot"; no cross-model pooling claim. §6 p.7–8 Threats to validity: representation parity threat; model scope threat ("results from one model may not transfer"); oracle overconstraint threat; external validity threat ("synthetic tasks may not capture all production complexity"). §7 p.8: primary endpoint uninformative because success = 0.0; 12 runs excluded for infrastructure timeouts. §8 p.8: "the principal contribution of this paper is therefore methodological and diagnostic."

## Limitations we observe (labelled OURS)
- OURS: With zero task success in every cell, none of H1–H3 can be tested as designed; only descriptive means of misuse counts are given, with no CIs, no per-budget breakdown, and no Wilcoxon/Holm results despite the stated plan (§5 p.6).
- OURS: The 0.5B quantized model is far below what web applications or agents would deploy; the semantic-misuse increase under schemas (0.93 → 3.03) may be an artifact of a very weak model producing more schema-valid but aimless calls once syntax is fixed.
- OURS: Overhead O and the token-efficiency metrics are defined (§4 p.4, §6 p.7) but no overhead numbers are reported — nothing usable for our RQ6.
- OURS: Diagnostic-quality ablation (C1–C3) and recovery-conditioned analysis are described (§6 p.7) but have no reported results; B and C are numerically identical in the pilot, so H2 is untested.
- OURS: "Semantic misuse" is about tool-choice/trajectory alignment (wrong tool, irrelevant query), not about semantically invalid field *values* inside a schema-valid call — a different notion from our field-level semantic validity.
- OURS: Sample sizes per cell are not stated (276 scored runs over 8 tasks × 3 conditions × 4 budgets × 3 seeds = 288 minus 12 excluded, inferred by us, not stated).

## Future work stated
§9 pp.8–9: (1) evaluate the same controlled design on additional open local models to assess model-dependent variability in semantic planning quality; (2) task calibration to reduce pure infrastructure bottlenecks so success-based endpoints become informative; (3) strengthen recovery policies with compact corrective prompts and bounded response formats.

## Relevance to our RQs (RQ1 structural-pass-but-semantic-fail; RQ2 frequency by field type; RQ3 LLM vs random/rule/human inputs; RQ4 violation types; RQ5 semantic layer detection; RQ6 latency/overhead; RQ7 trade-off)
- RQ1: PARTIAL. Explicitly separates interface validity from execution validity and semantic misuse (§3 p.3, §4 p.4) and finds schema conditions shift failures from interface misuse to schema-valid semantic misuse (§7 p.8: A 0.93 → B/C 3.03). But "semantic" here is trajectory-level, not field-value-level.
- RQ2: NONE. A per-category failure taxonomy including type mismatch, enum violation, constraint violation is planned (§6 p.7) but no per-category rates are reported.
- RQ3: NONE. Only LLM-generated tool calls; no random/rule/human input comparison.
- RQ4: PARTIAL (taxonomy only). Defines interface misuse subtypes (missing required field, type mismatch, invalid enum, malformed JSON, violated constraints) and semantic misuse (§4 p.4) — useful vocabulary; no frequencies.
- RQ5: PARTIAL. Trace oracles are a semantic detection layer for tool-call trajectories (§5 p.6); detection performance not evaluated (Cohen's κ planned, not reported).
- RQ6: NONE reported (overhead defined, no numbers).
- RQ7: NONE reported (cost trade-off is an experimental question (v), §6 p.6, without results).

## Potential gap / novelty evidence (quote LOCATION, e.g. "§5.2 p.7: authors state X"; short quotes only, ≤ 25 words)
- §1 p.2: "Interface misuse refers to violations of the tool input contract, whereas semantic misuse refers to calls that are schema valid but unproductive"
- §3 p.3: "We separate two notions of validity" — interface validity vs execution validity; execution validity "held constant across conditions."
- §7 p.8: "semantic misuse is higher in B/C (A = 0.93, B = 3.03, C = 3.03), indicating that remaining errors are dominated by schema valid but unproductive action choices."
- §8 p.8: "exposing the operational limits that remain when schema compliance improves but planning quality does not."
- Abstract p.1: "schema conditions reduce interface misuse but not semantic misuse."
- Gap evidence for us: the paper defines but never reports type/enum/constraint-violation frequencies (§6 p.7) or overhead (§4 p.4), and evaluates only one 0.5B model — field-level semantic validity in web/app inputs remains unmeasured.

## Terminology the paper uses for structural-vs-semantic validity
"interface validity" (schema/well-formedness) vs "execution validity" (runtime preconditions) (§3 p.3); "interface misuse" vs "execution failures" vs "semantic misuse" (§4 p.4); "schema valid but unproductive" (§7 p.8); "contract adherence" vs "semantic action quality" (Abstract p.1); "schema compliance" vs "planning quality" (§8 p.8); "structured field level validation diagnostics resembling compiler diagnostics" (§1 p.1); "information equivalence" (§1 p.1).
