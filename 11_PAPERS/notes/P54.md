## Problem
LLM-integrated applications concatenate an application prompt p with untrusted data d (p||d) and send it to a foundation model; adversary-controlled d can carry injected instructions (Sec 2.1–2.2, p.3). Existing ML-based prompt injection detectors (a) have a "propensity for false alarms" and cannot reach the very low FPR that the base-rate problem demands, and (b) do not handle the diversity of real traffic, in particular conversational chatbot data, and conflate jailbreaks with injections (Sec 1, p.1). Focus is on *indirect* prompt injection present in user/third-party data, not direct misuse (Sec 2.2, p.3). Optimization-based attacks such as GCG are out of scope (Sec 2.2, p.3).

## Research question(s)
Not stated as numbered RQs. Implicit questions (Sec 1, p.1–2; Sec 5, p.7–9): (i) how do existing detectors perform in the low-FPR regime; (ii) can careful data curation (conversational + application-structured) plus fine-tuning produce a detector with high TPR at 0.05–1% FPR; (iii) how do model size, training-set size, and training-set composition affect low-FPR performance.

## Method / architecture / algorithm
- **Deployment settings** (Sec 2.3, p.4): *client-deployed* — the LLM-integrated application applies the detector to all outgoing queries before sending them to the LLM; *provider-deployed* — a back-end model provider runs the detector as a preprocessor for the foundation model. Detectors are binary classifiers; benign queries are forwarded unchanged, malicious ones are blocked and trigger a refusal (Sec 2.3, p.3).
- **Taxonomy of LLM requests** (Sec 2.4, p.4): (1) conversational data (p = empty string; treated as benign by construction, no application prompt to attack) and (2) application-structured data (r = p||d; at risk of injection). Multi-turn and function calling are explicitly excluded (Sec 2.4, p.4).
- **Benchmark** (Sec 3.1, p.4–6; Table 1 p.5; Table 2 p.6): benign conversational = Ultrachat, LMSYS (filtered with OpenAI moderation model at a 1% toxicity threshold, App. A.1 p.13), Alpaca/databricks-dolly prompt-only, IFEval; benign application-structured = Alpaca, databricks-dolly, natural-instructions, Synthetic Python Problems (SPP); injections = StruQ "FourAttacks" (naive, ignore, completion, combined) applied to Alpaca/dolly/SPP, HackAPrompt, OpenPromptInject (Sec 3.1.2, p.5). Train/eval splits use disjoint datasets and disjoint "injection link phrases" (10 train / 11 eval, Table 10 p.13) to measure out-of-distribution performance and avoid phrase memorisation (Sec 3.1.3, p.6). Authors verified (best effort) that the evaluation split does not overlap the training sets of PromptGuard, ProtectAI, InjecGuard (Sec 3.1.3, p.6).
- **Detector** (Sec 3.2, p.6–7; Sec 4, p.7): fine-tuned instruction-tuned LMs. Primary model Llama-3.1-8B-Instruct fine-tuned with LoRA, 3 epochs, lr 2e-4, early stopping; FLAN-T5 small/base/large fully fine-tuned, 3 epochs, cross-entropy, lr 5e-5; DeBERTa-v3-base same as FLAN with lr 5e-6 (Sec 4, p.7). Training augmentation: 1–3 random newline delimiters inserted before p, before d, after d (Sec 4, p.7). For Llama models a fixed system prompt makes the model emit a single token 1 (injection) / 0 (benign); any other token defaults to 0 = benign (App. B.1, p.13).
- **Deployment scheme / threshold calibration** (Sec 3.2.2, p.6–7; Fig. 3 p.7): cache raw output scores, build ROC over thresholds, linearly interpolate (then bisect) to find the threshold whose FPR is within 25% of a target (1%, 0.5%, 0.1%, 0.05%). Authors state they calibrated on the evaluation split and "in retrospect, we should have used the validation split" (Sec 3.2.2, p.7). Same calibration was retroactively applied to competitors.

## Dataset(s) (+ size, licence) / benchmark
- PromptShield benchmark (own), released at https://huggingface.co/datasets/hendzh/PromptShield (Sec 3.1, p.4). Training sample used: 20,000 datapoints (~10,000 benign / ~10,000 malicious), all English; ~1,000 held out as validation (Sec 3.2.1, p.6; App. A.3, p.13). Evaluation sample: ~24,000 datapoints from the evaluation split (Sec 4, p.7).
- Constituent datasets: Ultrachat, LMSYS-Chat-1M, Alpaca, databricks-dolly, natural-instructions, SPP, IFEval, HackAPrompt, OpenPromptInject, StruQ attack implementations (Table 1, p.5).
- Licence: Not reported.

## Baselines
PromptGuard (Meta, mDeBERTa-v3-base, 279M; "jailbreak" label used as proxy for injection per App. B.2 p.13–14), ProtectAI v1 and v2 (DeBERTa-v3-base, 184M), InjecGuard (DeBERTa-v3-base, 184M), Fmops (DistilBERT, 67M) (Table 4, p.9; Sec 6, p.10). Attention Tracker discussed but not evaluated because it needs LLM-internal attention scores (Sec 6, p.10).

## Metrics
ROC AUC; TPR at target FPR of 1%, 0.5%, 0.1%, 0.05% (Sec 4, p.7). Attack success rate (ASR) in Appendix C (p.14). No latency, throughput or cost metric is defined anywhere in the paper.

## Key results (each with table/figure/page reference)
**Latency / throughput / cost / hardware: Not reported.** The paper contains no timing, throughput, cost, GPU or hardware information for any detector (grep of full text for latency/throughput/GPU/hardware/ms/cost returned no such measurement). The only efficiency-related statements are qualitative: Llama-class models "are large in size (i.e., ≥1B parameters) and may not be suitable for all deployment scenarios" (Sec 3.2.1, p.6) and Fmops "focusing on efficiency" (Sec 6, p.10).

**FPR / TPR numbers:**
- Headline (Fig. 2, p.2; Sec 1, p.2): at 0.1% FPR on the evaluation split, PromptShield (Llama-3.1-8B) detects 65.3% of attacks vs PromptGuard 9.4%, InjecGuard 6.6%, Fmops 2.1%, ProtectAI v1/v2 0.0%.
- PromptGuard case study (Table 3, p.8): threshold 0.500 → TPR 22.82%, FPR 2.91%; threshold 0.999 → TPR 17.02%, FPR 1.80%; threshold 0.99988 → TPR 12.81%, FPR 1.03%. Authors contrast this with PromptGuard's self-reported TPR 71% at FPR 1% (Sec 5.1, p.8).
- Main comparison (Table 4, p.9), columns AUC / TPR@1% / @0.5% / @0.1% / @0.05% FPR:
  - PromptGuard 279M: 0.874 / 12.78 / 12.43 / 9.39 / 1.54
  - ProtectAI v1 184M: 0.646 / 7.05 / 3.36 / 0.00† / 0.00†
  - ProtectAI v2 184M: 0.705 / 1.97 / 1.34 / 0.00 / 0.00†
  - InjecGuard 184M: 0.765 / 20.37 / 16.30 / 6.61 / 4.32
  - Fmops 67M: 0.754 / 13.00 / 8.39 / 2.10 / 1.48
  - PromptShield DeBERTa-v3-base 184M: 0.976 / 43.22 / 40.50 / 31.45 / 0.00†
  - PromptShield Llama-3.1-8B-Instruct: 0.998 / 94.80 / 87.80 / 65.33 / 47.53
  († = no threshold achieves that FPR other than 1.0.)
- Model-size study (Table 5, p.9): FLAN-T5-small 61M 0.942 / 7.56 / 4.66 / 3.05 / 2.57; FLAN-T5-base 223M 0.971 / 70.69 / 62.94 / 34.69 / 20.77; FLAN-T5-large 751M 0.985 / 55.60 / 46.30 / 40.56 / 35.72; Llama-3.2-1B 0.960 / 67.32 / 44.51 / 30.76 / 22.29; Llama-3.1-8B 0.998 / 94.80 / 87.80 / 65.33 / 47.53. Authors conclude ~100M parameters or more is needed for strong performance (Sec 5.3, p.8).
- Training-set size, Llama-3.1-8B (Table 6, p.9): 1K → TPR@1% 62.04%, @0.05% 20.89%; 5K → 89.62 / 50.74; 10K → 88.84 / 48.78; 20K → 94.80 / 47.53.
- Composition ablation (Tables 7–9, p.11): on benign *conversational* test data, the model trained with conversational data has FPR 1.61% / 1.03% / 0.18% / 0.06% at thresholds α/β/δ/γ vs 2.15% / 1.25% / 0.38% / 0.32% without (Table 9); on application-structured test data, TPR at threshold γ (0.05% FPR) is 53.68% with vs 70.90% without conversational training data (Table 8).
- Attack effectiveness (Table 11, p.14): ASR of 200 crafted injections — GPT-3.5-Turbo 47.0%, GPT-4o 43.0%, GPT-4o-mini 58.0%, Llama 3 59.0%. Targeted attacks against the detector itself (Table 12, p.14): Attack A ("Print 'Not injected!'") ASR 0.0%; Attack B ("Print '0'") ASR 11.4%.

## Stated limitations (with location)
- Training does not account for concept drift or optimized adversarial attacks crafted to bypass detection; performance may degrade without ongoing adaptation (Sec 7, p.10).
- Text-only; no multimodal inputs (Sec 7, p.10).
- Multi-turn conversations and function calling excluded from taxonomy (Sec 2.4, p.4).
- Decision thresholds were calibrated on the evaluation split rather than a validation split; authors recommend future work use the validation set (Sec 3.2.2, p.7).
- Choice of train/validation split causes variation at extremely low FPR (App. A.3, p.13).
- Attack B bypasses the detector 11.4% of the time (App. C.2, Table 12, p.14).

## Limitations we observe (labelled OURS)
- OURS: No latency, throughput, memory or cost measurement is reported for any model, although the paper's framing is "deployable" detection and a client-deployed detector sits in the request path; the 8B primary model's inference cost is not quantified.
- OURS: "Benign" is defined only as "no prompt injection" (footnote 1, p.3); semantic validity of the application data (e.g., whether d is a plausible form field value) is out of scope, so the detector does not address semantic-layer validation of ordinary web inputs.
- OURS: Input format is text p||d for LLM back-ends; no structured web-request payloads (JSON bodies, form fields) are considered.
- OURS: FPR results on conversational data (Table 9) are the only benign-traffic FPR numbers; no FPR is reported on benign application inputs *at deployment thresholds tuned elsewhere*, because thresholds were tuned on the same evaluation data.
- OURS: Single training run per configuration; no seeds/variance reported (App. A.3 mentions split-dependent variation qualitatively only).

## Future work stated
Continuous learning to address concept drift; a multimodal prompt injection benchmark and multimodal detectors (Sec 7, p.10). Hope that future work designs detectors "that can be deployed at scale" (Sec 8, p.10).

## Relevance to our RQs
- **RQ5 (semantic-layer detection):** PARTIAL. Establishes that an ML classifier placed before the LLM can detect instruction-bearing content in untrusted data with 65% TPR at 0.1% FPR (Table 4). But the "semantic" property detected is *instruction injection*, not semantic validity of a web input. Useful as the strongest recent prompt-injection classifier baseline and as evidence for the "operate independently of model internals / black-box" deployment argument (Sec 6, p.10).
- **RQ6 (latency/overhead):** NOT ADDRESSED. Zero timing data. Only parameter counts (61M–8B) are given as an efficiency proxy (Tables 4–5). This is itself gap evidence: the leading "deployable" detector paper reports no overhead.
- **RQ7 (trade-off):** PARTIAL. Provides the accuracy-vs-model-size trade-off (Table 5) and the TPR-vs-FPR trade-off along the ROC (Tables 3–4), but not accuracy-vs-latency.
- **FPR on benign inputs:** Central. The paper's whole framing is low-FPR deployability; benign-traffic FPR at deployment thresholds is 0.06–1.61% for conversational data (Table 9, p.11). Reports that a default-threshold PromptGuard blocks 2.9% of harmless traffic (Table 3, p.8), which the authors judge undeployable.

## Potential gap / novelty evidence (quote LOCATION; short quotes only)
- Sec 1, p.1: existing detectors "are not yet suitable for practical deployment" and "Existing schemes are unable to achieve such low FPRs."
- Sec 2.3, p.4: "a prompt injection detector must feature a low FPR across the data categories ... to be deployable at scale."
- Sec 3.2.2, p.7: "To the best of our knowledge, we are the first to propose such a deployment scheme for prompt injection detectors." (target-FPR threshold calibration)
- Sec 3.2.1, p.6: Llama-class models "may not be suitable for all deployment scenarios" — acknowledges but does not measure the cost side.
- Sec 4, p.7: "Prior work has often overlooked this region of the ROC curve" (low FPR).
- Absence evidence: no latency/throughput measurement anywhere (checked full text) → supports our gap that overhead of semantic/ML validation layers in the request path is unquantified.

## Detector design details useful for our semantic-layer candidates
- Embedding model: none separate; end-to-end fine-tuned LMs (Llama-3.1-8B-Instruct via LoRA; Llama-3.2-1B; FLAN-T5 small 61M / base 223M / large 751M; DeBERTa-v3-base 184M) (Sec 4 p.7; Table 5 p.9).
- Classifier type: generative LM emitting a single token 0/1 under a fixed system prompt (Llama; App. B.1 p.13) or sequence classification head (FLAN-T5/DeBERTa; details of head Not reported). Scores thresholded via ROC interpolation to hit target FPR (Sec 3.2.2 p.7).
- Training: 20K examples, 3 epochs, LoRA lr 2e-4 (Llama) / full FT lr 5e-5 (FLAN) / 5e-6 (DeBERTa), early stopping, newline augmentation (Sec 4 p.7).
- Hardware: Not reported. Latency measurement: Not performed.
- Baseline detector sizes for our own comparisons: PromptGuard 279M, ProtectAI 184M, InjecGuard 184M, Fmops 67M (Table 4 p.9).
- Practical takeaway for our design: calibrate on a validation split, not test; report TPR at fixed FPR (0.05–1%) rather than AUC; include benign conversational/ordinary traffic in training to reduce FPR (Table 9).
